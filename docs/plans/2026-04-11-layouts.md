# Layouts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1 of user-authored session layouts: KDL files in `~/.config/roux/layouts/` and bundled built-ins that describe a pane tree of spawn profiles, selectable at session-creation time in `NewSessionDialog` and applied in one atomic walk.

**Architecture:** Layouts are pure inputs, not state. A new Rust parser reads KDL into `LayoutSpec` types (mirroring `SpawnProfile`), a loader walks built-in (`include_str!`) and user directories, two Tauri commands expose both lists to the frontend. A frontend walker `applyLayoutToSession` builds the final `LayoutNode` tree in a single shot (bypassing `splitPane`/`insertLeaf` to preserve structure and sizes), spawns PTYs, creates pane instances, writes the tree to `sessionLayouts`, and runs profiles. `NewSessionDialog` gains a layout dropdown above the profile picker.

**Tech Stack:** Rust (`kdl-rs`, `specta`, `serde`, `thiserror`), Svelte 5 runes, Tauri 2, existing xterm/PTY stack.

---

## Context

Spawn profiles (shipped in #34) let a single pane run a specific command with env/setup/startup behavior. Layouts are the next natural step: a named, versionable description of an **entire session shape** — what panes exist, how they split, which profile runs in each. KDL is the source format because it is human-friendly, has good error spans, and is already the Zellij convention that power users will recognize.

Non-goals for v1:

- No "apply layout to existing session" — layouts only create new sessions.
- No "save current session as layout" — reverse serialization is a separate project.
- No inline layout editor modal — file-based editing only.
- No project-level layouts. Reserved for when project-scoped profiles land.
- No stacked splits in layouts.

## KDL Schema

```kdl
layout {
    name "Python dev"
    description "Claude on the left, tests running on the right"

    pane split_direction="horizontal" {
        pane profile="python-claude" size=60
        pane split_direction="vertical" size=40 {
            pane profile="plain-shell" size=60
            pane name="tests" size=40 {
                // inline spawn profile
                display_name    "Tests"
                kind            shell
                setup_command   "source .venv/bin/activate"
                startup_command "pytest --watch"
                startup_behavior run
            }
        }
    }
}
```

**Rules:**

- Exactly one top-level `layout` node. Required `name` attribute; optional `description`.
- Every non-top-level `pane` is either a **leaf** (has `profile="id"` OR an inline profile block, not both) or a **container** (has `split_direction="horizontal"|"vertical"` and children).
- `size=N` on a child is treated as a proportional weight; siblings' sizes are normalized to fractions summing to 1.0 at apply time. Sizes out of `[0, 100]` are a parse error.
- Inline profile fields mirror `SpawnProfile` verbatim (`display_name`, `kind`, `command`, `setup_command`, `startup_command`, `startup_behavior`, `env`). Unknown fields are a parse error.
- Filename stem is the stable layout id. `name` is for display only.
- `cwd` leaf attribute is **parsed** in v1 but **not honored** — reserved for follow-up. Parse error if specified to avoid silent drift.

## Architectural Invariant

**Layouts are inputs, not state.** Once `applyLayoutToSession` finishes, the session is indistinguishable from one built by hand. User edits (splits, closes, moves) never round-trip back to the layout file. The existing `pane_state.ts` persistence captures the resulting tree and pane descriptors and restores them on next launch; the layouts registry is **not consulted** at restore time.

Optional display-only metadata: add `layout_id: Option<String>` and `layout_name: Option<String>` to `Session` so the tab bar can show a "from layout X" badge. Covered by `#[serde(default)]`, no migration required.

## Why the walker does NOT call splitPane

`splitPane` is built for the incremental "add one pane next to focus" path; it calls `insertLeaf`, which flattens same-direction splits and normalizes sizes for the _current_ tree. That is correct for iterative user splits and exactly wrong when you already know the entire tree shape up front.

`applyLayoutToSession` instead:

1. Walks `LayoutSpec.root` in one DFS pass, minting `paneId` + `ptyId` per leaf.
2. Resolves each leaf's profile ref (registered → lookup `profileRegistry`; inline → pass through). A missing registered id fails hard **before any PTY is spawned**.
3. For each leaf, calls `spawnShell(ptyId, session.worktreePath, session.id, paneId)`. Failures unwind earlier spawns via `killPty`.
4. For each leaf, calls `createPane({ id, type: "shell", ptyId, spawnProfileRef, name })`.
5. Builds the final `LayoutNode` tree in one shot, substituting paneIds and normalizing KDL sizes onto `SplitNode.sizes`.
6. Writes the tree via a single `sessionLayouts.update` (atomic against the auto-save debouncer).
7. For each leaf, calls `initTerminal(paneId)` + `attachPtyListeners(...)` (dynamic import of `$lib/panes/terminals`).
8. For each leaf, calls `runProfileInPane(ptyId, resolvedProfile)`. Per-leaf failures are collected and surfaced as a single notification, matching the split-with-profile pattern in `commands/panes.ts`.
9. Focuses the first DFS leaf.

**Three reasons** for one-shot tree construction:

- **Exact size preservation.** `splitPane` has no size param and teaching it one ripples into every callsite.
- **No flattening hazard.** `insertLeaf` can silently reshape nested trees.
- **Atomicity.** One `sessionLayouts.update` avoids debouncer churn on half-populated intermediate states.

The tradeoff — ~30 lines of tree-construction that partially duplicate `splitPane` — is worth it and specific enough to layouts that sharing would produce worse code on both sides.

## Persistence interaction

After `applyLayoutToSession` returns, the session is a regular session with a regular pane tree. Existing `pane_state.ts` persistence captures `sessionLayouts.get(sessionId)` plus each pane's descriptor (including `spawnProfileRef`) and restores it on next launch. The layouts registry is not consulted at restore time.

```rust
pub enum LayoutParseError {
    #[error("kdl parse error at {line}:{column}: {message}")]
    Syntax { line: usize, column: usize, message: String },
    #[error("{message} at {line}:{column}")]
    Schema { line: usize, column: usize, message: String },
}
```

`LayoutParseError` is not `specta::Type`-derived — it renders to `String` at the IPC boundary, matching every other service error in Roux.

**Public parser entry point:**

```rust
pub fn parse_layout_kdl(
    id: impl Into<String>,
    source: LayoutSource,
    src: &str,
) -> Result<LayoutSpec, LayoutParseError>;
```

The parser uses `kdl::KdlDocument::parse(src)`, walks the single top-level `layout` node, and recursively builds `LayoutPaneNode` from each `pane` node. Every error path carries the `KdlNode`'s span so messages are IDE-style. The `id` is passed in (not read from source) because the loader derives it from the filename.

This is the only module in the codebase that touches `kdl-rs`. Nothing above this layer sees `KdlDocument` / `KdlNode`.

**Loader shape:**

```rust
pub struct LoadedLayouts {
    pub layouts: Vec<LayoutSpec>,
    pub errors: Vec<LayoutLoadError>,
}

pub struct LayoutLoadError { pub path: PathBuf, pub message: String }

pub fn load_builtin_layouts() -> LoadedLayouts;
pub fn load_user_layouts() -> LoadedLayouts;
```

Built-ins use `include_str!` so the binary is self-contained. `load_user_layouts` creates `~/.config/roux/layouts/` if missing, ignores anything that is not a regular `*.kdl` file (dotfiles, subdirs, symlinks — same anti-symlink guard as `paths::copy_dir_skip_existing`), parses each file, and splits results into successes / errors. **A failed parse does NOT poison the rest of the load.**

Filename → id: strip `.kdl`, lowercase, keep the stem otherwise. `My Layout.kdl` becomes id `my layout` (space-preserved with a non-fatal warning — slug canonicalization can come later without breaking anything).

```ts
import { writable, derived, type Readable } from "svelte/store";
import { commands } from "$lib/bindings";
import type { LayoutSpec } from "$lib/bindings";

export type { LayoutSpec } from "$lib/bindings";

const builtinLayouts = writable<LayoutSpec[]>([]);
const userLayouts = writable<LayoutSpec[]>([]);

export const layoutRegistry: Readable<Map<string, LayoutSpec>> = derived(
  [builtinLayouts, userLayouts],
  ([$builtin, $user]) => {
    const map = new Map<string, LayoutSpec>();
    for (const l of $builtin) map.set(l.id, l);
    for (const l of $user) map.set(l.id, l); // user wins on collision
    return map;
  },
);

export const layoutList: Readable<LayoutSpec[]> = derived(
  layoutRegistry,
  ($reg) => Array.from($reg.values()),
);

  builtinLayouts.set(await commands.getBuiltinLayouts());

  userLayouts.set(await commands.getUserLayouts());

export function resolveLayoutById(id: string): LayoutSpec | null {

}
```

```ts
if (selectedLayout) {
  // Layout path: always createSessionShell + applyLayoutToSession;
  // never the legacy Claude path (see "Legacy Claude path caveat").

    repoPath,
    name,
    worktreePathArg,
```
